How it decides

Four verdicts, and each one explains itself.

AEGIS runs unattended, so it doesn't park decisions in a queue nobody reads. What makes that safe isn't confidence. It's that every guess can undo itself.

Confirmed

Blocked for good

Exploit-class evidence, a known-bad indicator, a stolen decoy credential, or a brute force that was counted and kept going.

Permanent on every layer. A real attack is never quietly released.
Provisional

Blocked, then lifted

Anything triage can't classify. It's stopped now, and the block expires on its own if the source goes quiet.

6 hours by default, longer when severity is critical. A second offence is permanent.
Held

Raised, not blocked

Shared egress such as Cloudflare WARP or iCloud Private Relay, where one address is thousands of people, or an address only an endpoint agent vouches for.

Incident opened. The block waits for your approval.
Safe

Never touched

Your safelist, private and VPN ranges, and verified crawlers and CDNs. One shared gate that every detection path consults.

No block, no incident, whichever part of AEGIS saw it.

Guardrails fail closed: an action type nobody configured, or a policy that doesn't parse, waits for approval instead of running automatically.

Pipeline

From a log line to a firewall rule.

Four stages, one record. Every block carries the reason it was made, and AEGIS keeps checking that it's still true.

01

Detect

  • Inline request inspection: payloads, probe paths, scanner fingerprints
  • Live tailing of PM2 or journald logs: brute force, rate, port scans
  • Sigma correlation: 164 rules and chains that link recon to exploitation
  • Endpoint agent for processes, files, registry and connections
  • Honeypots, and read-only health checks for MikroTik switches
02

Decide

  • Confirmed or provisional, from the evidence on record
  • Safelist and shared-egress gates, the same on every path
  • Per-action guardrails that fail closed
  • Optional AI triage, with a deterministic fallback for every call
03

Enforce

  • Firewall agent on your gateway, with iptables (a Raspberry Pi works)
  • 403 blocklist in the API's own middleware
  • Local pfctl or iptables, when you opt in
A block only counts as done when a layer actually took it.
04

Keep honest

  • Provisional blocks expire on schedule
  • A failed unblock is retried, never marked as done
  • A live block missing on the agent is sent again
  • An unreachable agent is never read as an empty blocklist
Deception

Let them steal something.

An SSH honeypot on :2222 and an HTTP decoy on :8888 hand out bait: fake .env files and keys, each one unique. When an attacker tries one against a real service, it's no longer a guess.

  • Breadcrumb reuse is always confirmedA critical incident and a permanent block, with the session that leaked it attached.
  • Every session is profiledCredentials tried, commands typed and tools recognised, kept on the attacker's record.
  • Works offlineDecoy content comes from templates when no AI is configured.

AI, optional

A tool here, not a dependency.

Nothing in the path from event to block needs a model. When you do connect one, it's held to the same rules as any other input.

  • Rules it writes are tested on your trafficAEGIS can draft a detection rule, but it's replayed against real events first and stays alert-only until you approve it.
  • The assistant proposes, you decideIt reads text attackers wrote, so it can't add to the safelist, and it blocks only an address your own message names.
  • Secrets stay out of promptsProvider keys, bot tokens and webhook URLs are redacted before anything reaches a model.

Install

Running in three minutes.

Docker and Docker Compose, 2 GB of RAM (4 GB is comfortable). An AI key is optional.

terminal 
$ git clone https://github.com/alejadxr/AEGIS.git && cd AEGIS
$ cp .env.example .env
# in .env: set AEGIS_SECRET_KEY (openssl rand -hex 32)
# and AEGIS_ADMIN_PASSWORD. Compose won't start without them.
$ docker compose up -d

Then

localhost:3000
Dashboard. Sign in as admin@aegis.local.
localhost:8000
API, with OpenAPI docs at /docs.
releases

Real firewall enforcement is opt-in with AEGIS_REAL_FW=1, and the gateway agent lives in firewall-agent/.

FAQ

Questions people actually ask.

What happens when AEGIS blocks the wrong address?
Unless the attack was confirmed, the block is provisional and lifts itself, after 6 hours by default. You can also lift any block yourself from the dashboard or the API. Addresses on your safelist, private ranges and verified crawlers are never blocked in the first place.
Does it need an AI API key?
No. Set AEGIS_AI_MODE=disabled and every AI call site uses its deterministic fallback. Sigma rules, chain detections, blocking and expiry never use a model. If you do want AI, OpenRouter, OpenAI, Anthropic and local Ollama are supported.
Where does the blocking actually happen?
In up to three places: a small firewall agent on your gateway that manages an iptables chain, the API's own 403 middleware, and the host's pfctl or iptables if you enable AEGIS_REAL_FW=1. Without any of them, AEGIS still detects and records everything.
Do I need the endpoint agent?
Only for endpoint detections. Request, log, honeypot and network rules work without it. About fifty of the rules read process, file, registry or connection events, and those see something only on hosts that run the agent, or on the AEGIS host itself.
How was 1.7.33 audited?
A static review of the whole codebase with Claude Mythos 5.2, then each fix implemented with tests. It found 53 issues across four severities. It didn't attack a live system, and some modules were out of scope: the release notes name them, along with the findings that are still open.
How do I report a vulnerability?
Privately, following SECURITY.md. Please don't open a public issue for it.
